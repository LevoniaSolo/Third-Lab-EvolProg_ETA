# ЛР3. Эволюционный отбор признаков

Вариант 17, трек A. NSGA-II ищет бинарные маски длины 18, одновременно минимизируя долю ошибок на validation и число выбранных признаков. Качество на графиках выражено через accuracy, то есть единицу минус доля ошибок.

## Запуск

Нужен Python 3.10 или новее. Команды выполняются из папки `lr3`.

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m unittest -v
python main.py --runs 2 --output results_trial
```

Для итоговой серии из 20 независимых запусков используется команда `python main.py`. Она читает `config.json` и сохраняет результаты в `results/`. Параметр `--config` позволяет передать иной JSON, а `--runs` переопределяет число запусков. При повторном запуске с тем же каталогом его файлы результатов перезаписываются.

## Данные, модель и поиск

- Генератор создаёт 1000 сбалансированных наблюдений. Признаки `x01–x05` имеют сдвиг среднего в зависимости от класса, `x06–x10` получаются из их линейных комбинаций с добавлением шума, а `x11–x18` содержат независимый шум. Seed генерации, seed стратифицированного разбиения 60/20/20 и seed эксперимента заданы отдельно. Все запуски используют одни и те же данные и разбиение.
- Классификатор — регуляризованный линейный дискриминант. Для каждой маски средние, масштабы и параметры классификатора оцениваются по train. Validation используется для подсчёта ошибок, а кэш каждой маски действует в пределах одного запуска. Целочисленное число ошибок даёт тот же порядок сравнения, что и доля ошибок, поскольку размер validation фиксирован.
- NSGA-II реализован в `nsga2.py`. Начальная популяция состоит из случайных непустых масок. Бинарный турнир сравнивает ранг и расстояние до скопления. Одноточечный кроссовер и независимая побитовая мутация дают потомков. Пустой маске случайно включается один признак. Элитистский отбор заполняет новую популяцию фронтами из объединения родителей и потомков и обрезает последний фронт по расстоянию до скопления.
- Объединённый фронт строится по всем маскам, встреченным за серию. Для крайних решений берутся точки с наименьшим числом признаков и с наименьшей validation-ошибкой. Компромиссная точка выбирается среди внутренних по минимальному евклидову расстоянию до идеальной точки после нормировки по диапазонам фронта. При совпадении критериев выбирается лексикографически меньшая маска. При фронте из менее чем трёх точек программа сообщает о недостающих ролях.
- После выбора масок модели для этих решений и модели на всех 18 признаках переобучаются на train + validation и оцениваются на test. Эта оценка характеризует выбранные решения. На графике фронта у базовой модели показана validation-оценка после обучения на train.

## Сравнение со взвешенной суммой

Для той же совокупности оценённых масок проверяется критерий `w × validation_error + (1 − w) × (n_features − 1) / 17` для всех `w` от 0 до 1. Для каждой точки фронта пересекаются ограничения на вес, при которых её значение суммы не превосходит значения суммы у остальных точек. Сравнение выполняется точно в рациональных числах. Для внутреннего веса доминируемые точки не могут выиграть, а на концах диапазона при равенстве суммы рассматриваются недоминируемые решения.

Фиксированный вес сводит выбор к одной числовой оценке и выражает предпочтение между качеством и размером набора. Пустой интервал означает, что никакой вес не выбирает эту точку среди найденных решений. Интервал из одного значения означает ничью при конкретном весе. Анализ поддерживаемости проверяет, какие компромиссы может выразить взвешенная сумма на найденных данных. Сравнение эффективности двух алгоритмов поиска потребовало бы отдельной серии запусков со скалярной фитнес-функцией и сопоставимым бюджетом.

## Файлы результатов

| Файл | Содержимое |
| --- | --- |
| `dataset.csv`, `dataset_metadata.json` | Значения признаков, метки, части выборки, параметры генерации, типы признаков и индексы разбиения |
| `experiment.json` | Фактическая конфигурация, seed каждого запуска, версии библиотек и размеры объединённого фронта |
| `runs.csv`, `history.csv` | Итоги запусков и динамика по поколениям, включая начальную популяцию как поколение 0 |
| `summary.csv` | Минимум, среднее, медиана, стандартное отклонение и максимум по финальным значениям гиперобъёма, лучшей validation accuracy и минимального числа признаков из `runs.csv` |
| `evaluated_masks.csv` | Каждая оценённая маска один раз за запуск и её значения критериев |
| `run_fronts.csv` | По одному представителю точки для фронта всех найденных масок и фронта последней популяции каждого запуска |
| `pareto_front.csv` | Все маски объединённого фронта, включая равные по критериям |
| `weighted_sum.csv` | Точные интервалы весов и признаки поддерживаемости для фронтов отдельных запусков и объединённого фронта |
| `selected_masks.csv` | Характерные решения, базовая модель и их оценки на validation и test |
| `pareto.png`, `history.png` | Объединённый фронт и динамика поиска по запускам |

В `history.csv` число рассмотренных особей включает повторы, а `unique_masks` считает отдельные маски. Гиперобъём рассчитывается по фронту всех масок, просмотренных к текущему поколению. При минимизации обоих критериев опорная точка равна (доля ошибок 1, 19 признаков), площадь нормируется на площадь прямоугольника между ней и точкой (доля ошибок 0, 1 признак).

В `summary.csv` стандартное отклонение описывает разброс наблюдаемых запусков с `ddof=0`. Дисперсия делится на число запусков. В таблице указаны число запусков и использованное значение `ddof`.
